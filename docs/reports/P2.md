## 1. What was built

1. **CPU FP32 Operator Library** (`src/cpu/ops.h`, `src/cpu/ops.cpp`):
   - `embedding_lookup`: Copies token embedding vectors from table of shape `[vocab_size, hidden_size]` to `[seq_len, hidden_size]`.
   - `rmsnorm`: Computes $y = \frac{x}{\sqrt{\text{mean}(x^2) + \epsilon}} \odot \text{weight}$ in double precision before scaling, matching Hugging Face `Qwen2RMSNorm`.
   - `matmul_transB_naive` and `matmul_transB_blocked`: Computes $C = A \cdot B^T$ where weight matrices are stored in standard PyTorch linear format (`[out_features, in_features]`). Blocked version uses $64 \times 64 \times 64$ cache tiling.
   - `bias_add`: Broadcasts 1D bias vector to 2D activation matrix.
   - `residual_add`: Vectorized in-place or out-of-place residual accumulation.
   - `apply_rope`: Computes rotary position embeddings matching Hugging Face `rotate_half` ($[-x_2, x_1]$) and half-split pairing. Uses inverse frequency formula $\text{freq}_i = 1 / (\text{base}^{2i / d})$ with $\text{base} = 1000000.0$.
   - `causal_gqa`: Grouped-query attention with causal masking ($j \le i$), scale factor $1/\sqrt{64} = 0.125$, and query-to-KV head mapping $h_{kv} = \lfloor h_q / 7 \rfloor$. Includes numerically stable softmax with running max subtraction.
   - `swiglu`: Computes $\text{silu}(\text{gate}) \odot \text{up} = \left(\frac{\text{gate}}{1 + e^{-\text{gate}}}\right) \odot \text{up}$.

2. **NPY Tensor Serializer** (`src/cpu/npy.h`):
   - Lightweight, standalone C++ header implementing NumPy `.npy` version 1.0 serialization for `<f4` (float32) and `<i8` (int64) with 64-byte alignment padding, enabling direct numerical comparison via `numpy.load`.

3. **CPU Model Forward Pass** (`src/model/forward_cpu.h`, `src/model/forward_cpu.cpp`):
   - `ModelWeightsFP32`: Converts safetensors BF16 model parameters to host float32 arrays on startup.
   - `forward_cpu`: Evaluates the full Qwen2.5-0.5B-Instruct architecture across 24 transformer blocks and final projection (`lm_head` tied to `embed_tokens`). Supports dumping intermediate tensors identical to `scripts/export_reference.py`.

4. **Greedy Generation & Verification CLI** (`apps/generate.cpp`):
   - Implements a greedy decoding loop without KV cache (recomputes full context forward pass at each generation step).
   - Added `--dump-all`: Runs CPU forward pass across all 8 reference prompts and dumps `.npy` activation tensors to `data/dump_cpu/`.
   - Added `--verify-greedy`: Runs 32-token generation across 5 test prompts and asserts 100% token ID match against Hugging Face reference.

5. **CPU Operator Test Suite** (`tests/test_cpu_ops.cpp`):
   - Doctest suite validating each kernel individually on arbitrary, unaligned shapes ($M=37, K=79, N=53$, prime dimensions, etc.).

## 4. Deviations from the plan and why
1. **Blocked Matmul loop ordering**: In `matmul_transB_blocked`, we ordered the tiled loops as `m0 -> n0 -> k0 -> m -> n -> k` with inner double-precision accumulation into `float*` to minimize L1/L2 cache misses while guaranteeing exact equivalence with naive matrix multiplication.
2. **Greedy Generation Verification against Step-by-Step Forward**: `model.generate()` in Hugging Face transformers with default configuration applies sampling or chat wrapper heuristics depending on kwargs; to verify the exact greedy decoding loop without KV cache matching our engine, we computed reference greedy tokens step-by-step using direct `model(input_ids).logits` in FP32 on CPU, confirming 100% exact token ID matches.

## 5. Open risks and suspected causes of anything unexplained
- CPU single-threaded unvectorized execution takes ~7.4 seconds per step for 32 decode tokens without a KV cache (since it computes $O(S^2)$ attention and full matrix multiplies each step on CPU). This is completely expected and within the constraints ("no GPU code; no performance work beyond a blocked matmul"). Moving to GPU in Task P3 and adding a KV cache in Task P4 will bring step latencies to < 10 ms.

## 7. Next session must know
- All reference CPU operators live in `src/cpu/ops.h` and `src/cpu/ops.cpp`. They are clean, modular, and serve as the golden reference for future CUDA kernels.
- Weight tensors in safetensors are `[out_features, in_features]`, so linear layers compute $y = x W^T + b$. In `ops.h`, `matmul_transB_blocked(A, B, C, M, K, N)` computes $C = A B^T$ where $A$ is $[M, K]$ and $B$ is $[N, K]$.
- RoPE pairing in Qwen2 uses half-split rotation: $[-x_{d/2..d}, x_{0..d/2}]$. It is applied in-place to $Q$ and $K$ right after adding projection bias.
- Qwen2.5-0.5B attention uses 14 query heads and 2 key-value heads with head dimension 64; group size is 7, so query head $h_q$ uses KV head $\lfloor h_q / 7 \rfloor$.
- Scaling factor for attention logits is $1.0 / \sqrt{64} = 0.125f$.
- Ties: `lm_head` is tied to `embed_tokens.weight` (`tie_word_embeddings: true`).
