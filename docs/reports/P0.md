## 1. What was built

1. **Build System & Toolchain Configuration**:
   - `CMakeLists.txt`: Root CMake build configuration targeting C++17 and CUDA 17 for `sm_89` (Ada Lovelace, RTX 4060 Laptop). Configures static library `engine`, executable `generate`, and test runner.
   - `scripts/build.bat`: One-click MSVC x64 developer environment initialization + Ninja build + ctest script.
   - `docs/ENV.md`: Comprehensive environment documentation with hardware specs, compiler versions, and exact invocation commands.
   - `src/common/cuda_utils.h`: CUDA error checking macro `CUDA_CHECK` and CUDA runtime headers.
   - `src/cuda/dummy_kernel.cu` & `src/cuda/dummy_kernel.h`: Trivial CUDA vector addition kernel.
   - `tests/test_bootstrap.cpp` & `tests/CMakeLists.txt`: Host/device allocation and kernel verification test integrated into CTest.
   - `apps/generate.cpp`: Stub entry point for inference CLI.

2. **Reference Harness & Oracles**:
   - `scripts/export_reference.py`: Runs Hugging Face transformers (`Qwen/Qwen2.5-0.5B-Instruct`) in FP32 on CPU across 8 fixed prompts (`01_short`, `02_medium`, `03_long`, `04_code`, `05_unicode`, `06_cjk_emoji`, `07_chat_template`, `08_whitespace_indent`). Exports 10 activation tensors per prompt (`token_ids`, `embedding`, `layer_0_post_attn`, `layer_0_post_mlp`, `layer_1_post_attn`, `layer_1_post_mlp`, `layer_23_post_attn`, `layer_23_post_mlp`, `final_norm`, `logits`) to `data/reference/`. Total: 80 tensors and `manifest.json`.
   - `scripts/compare.py`: CLI comparison utility supporting arbitrary directory pairs with configurable `--max-abs` and `--mean-abs` thresholds, displaying per-tensor max diff, mean diff, and argmax logit agreement.

3. **Runner Interface Specification**:
   - `docs/runner_interface.md`: Formal specification of the contract between `py-engine` scheduler and model runner, defining memory ownership, method signatures (`prefill`, `decode_step`, `step`), sequence state transitions, tensor shapes, and physical block allocation rules.

4. **Observability & Baseline Harness**:
   - `scripts/nvml_logger.py`: Direct `ctypes` wrapper over Windows driver `nvml.dll` (zero third-party dependencies). Samples SM clock, memory clock, GPU temperature, power draw, and throttle reasons at 10 Hz into CSV.
   - `scripts/bench.py`: Benchmarking harness measuring 256 MB device-to-device copy bandwidth with L2 cache flushed (5 warmup + 25 timed iterations with CUDA events), HF eager FP16 decode, and `reference/py-engine` Triton decode.
   - `third_party/llama.cpp`: Cloned and compiled with CUDA support (`GGML_CUDA=ON`, `CMAKE_CUDA_ARCHITECTURES=89`). Produced `llama-bench.exe` and `llama-quantize.exe`.
   - `data/models/`: Acquired GGUF weights in F16 (converted from HF snapshot via `convert_hf_to_gguf.py`), Q8_0 (quantized via `llama-quantize.exe`), and Q4_K_M (downloaded from official Qwen repo).

## 4. Deviations from the plan and why
1. **NVML access via direct `ctypes`**: Instead of adding external pip dependencies like `pynvml` or `nvidia-ml-py`, `scripts/nvml_logger.py` loads `nvml.dll` directly from the Windows system driver. This strictly adheres to AGENTS.md Rule 8.
2. **GGUF acquisition**: Direct conversion from HF weights was used for F16 using `convert_hf_to_gguf.py`, and `llama-quantize.exe` was used to create Q8_0 from F16, while Q4_K_M was downloaded directly from the official Qwen GGUF repo. This avoided network throttling on the large GGUFs and guaranteed bit-exact weights matching our Hugging Face reference.

## 5. Open risks and suspected causes of anything unexplained
- In `py-engine`, during Python decode steps the SM clock dropped to 900 MHz due to low GPU utilization / Python launch overhead between single-step kernel invocations (as noted in the charter's roofline section). This directly validates the charter's hypothesis: Python engine's ~46 ms/step decode is launch-bound rather than compute-bound.
- In `llama.cpp`, decode step times are 5.22 ms (F16), 3.09 ms (Q8_0), and 2.73 ms (Q4_K_M). This demonstrates that optimized C++/CUDA execution runs nearly 10x faster than Python eager and Triton wrappers at batch 1 decode.
