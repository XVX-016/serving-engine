## 1. What was built and verified

1. **Custom FP16 GEMV Kernel (`src/cuda/gemv.cu`, `src/cuda/kernels.h`)**:
   - Implemented `gemv`, `gemv_bias`, and `gemv_residual`.
   - Grid layout: each output neuron $n \in [0, N-1]$ is mapped to exactly one warp (32 threads).
   - Thread $t$ iterates across inner dimension $K$ with stride 32, loading elements in FP16 and accumulating in 32-bit registers (`float`).
   - Warp-level sum reduction using `__shfl_down_sync`.
   - Thread 0 applies compile-time dispatched epilogue (`EpiNone`, `EpiBias`, or `EpiResidual`) and writes the single half output element.
2. **Epilogue Fusion in Decode Path (`src/model/forward_gpu.cu`)**:
   - Replaced `matmul_transB` + `bias_add` for Q, K, V projections with `cuda::gemv_bias`.
   - Replaced `matmul_transB` for Gate and Up projections with `cuda::gemv`.
   - Replaced `matmul_transB` + `residual_add` for O projection and Down projection with `cuda::gemv_residual` into `buffers.hidden_states`.
   - Eliminated all 72 `bias_add` and 48 `residual_add` kernel launches during decode.
3. **Unit Tests (`tests/test_cuda_ops.cpp`)**:
   - 25 random shapes per variant against CPU reference (`cpu_gemv`).
   - Verified clean under `compute-sanitizer --tool memcheck`.

## 5. Open risks and suspected causes of anything unexplained
1. **Thermal Headroom on Laptop**: Long uninterrupted generation sweeps across large contexts cause the RTX 4060 Laptop to hit `SW_THERMAL_SLOWDOWN` and `SW_POWER_CAP` (up to 88W power spikes), causing step latencies to temporarily rise if GPU is not given short idle intervals between runs.
2. **Attention Remains Bottleneck**: `decode_gqa` now accounts for **70.4%** (12.55 ms) of total decode time due to serial uncoalesced attention over sequence length (1.01 GB/s vs 228 GB/s peak). This is the explicit focus of Task P7 (Split-KV).
